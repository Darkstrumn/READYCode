# Pocket READY. desktop protocol client

The client uses `/pocketready/v1/`, matching Pocket READY. PR #47. The Ultimate client keeps its independent `/v1/` API; there is no `/pr/` naming convention to preserve. Control/output support depends on Pocket READY. PR #48 (after #46 and #47). The desktop target/editor window is the following stacked READYCode PR, not part of this transport slice.

`PocketReadyClient` retains its injected, caller-owned HttpClient. **Configure its handler with AllowAutoRedirect=false** before using authenticated mutations; never silently follow a redirect carrying source. Tokens are attached per request, never to DefaultRequestHeaders, URLs, files or settings. Discovery remains unauthenticated; control requires the temporary token from the phone's explicit ALLOW CONTROL action. No desktop method grants control. Plain HTTP does not encrypt the token/source; use a trusted LAN. The WPF host supplies an owned redirect-disabled client and disposes it on close.

`GetControlAsync` validates advisory instance/controller/lease/generation/phase. `PocketReadyOperation.Create` preserves exact UTF-8 BASIC source (including optional labels, Unicode and line endings), assigns one operation ID and enforces source/input bounds. `ExecuteAsync` POSTs once, polls its ticket with a cancellable delay and returns an application receipt. It never automatically retries a mutation. Keep the immutable envelope after timeout, cancellation or transport failure: an action may already have applied. Deliberately retry that same envelope/ID or use `GetReceiptAsync`; do not manufacture a new ID for an uncertain action. A rejected application receipt is distinct from a delivery rejection/HTTP exception. Neither applied nor HTTP 202 means program completion.

`ReadOutputAsync` retrieves at most two events, validates monotonic next/latest cursors, bounds text and located diagnostic metadata and exposes gap warnings. It is lossy observation, not a Bifrost terminal spool. `PocketReadyContract.SourceId` matches the interpreter's UTF-16 FNV source identity for safe diagnostic navigation. Do not navigate into an edited document or another library merely because its line number exists.

All awaits use ConfigureAwait(false). Header/body reads and ticket polling share caller cancellation and an overall configurable deadline (15 seconds by default). JSON depth is bounded; discovery remains 64 KiB and control responses 256 KiB, checking both declared and actual bytes. Strict UTF-8 rejects invalid bytes. Requests/responses/streams/deadline sources are disposed. The caller's HttpClient remains alive. Source limits are 640 KiB UTF-8, JSON requests 4 MiB, input 1–16 UTF-16 code units. Unknown additive metadata/minor versions remain compatible; required fields and incompatible identities/major versions fail.

C64U/VICE, PRG conversion, assembly and debug APIs are unchanged. The application is still .NET 8 WPF. Run `dotnet test ReadyCode.Tests/ReadyCode.Tests.csproj -c Debug` on Windows; CI builds the full application and existing tests. HTTP doubles cover namespace/proxy paths, exact source, receipt/ticket identity, no implicit retry, cancellation, source/response limits and UTF-8. Real Windows-to-S24 networking and WPF interaction remain physical acceptance gates. This is a user-authorized stack; merge the client PR before its desktop UI child, and server #46 → #47 → #48 before testing the combined feature.

## Desktop editor and target window

Open **Pocket READY. → Open BASIC editor and LAN target…**. A current `.pbas` tab is shared with the target window. A C64 BASIC tab is copied into a new unsaved `Untitled.pbas` tab; its original document/file is untouched. Assembly, binary, compare and disk-backed tabs are not converted into runnable Pocket READY. source. The target window closes if its source tab is closed. Its shared edits mark that tab dirty even when another main tab is selected. Save source/Ctrl+S stages complete UTF-8 without a BOM in a sibling temporary file before replacement (cleaning the stage on cancellation/failure), and only clears the dirty marker if no edits occurred during the write.

`.pbas` selects the explicit extended dialect when reopened. `.bas` retains its C64 default for existing projects; importing it through the Pocket READY. menu creates the separate dialect copy. The profile supplies extended keyword highlighting/completion, physical line numbers, native case/paste and UTF-8 statistics. It bypasses C64 ROM token matching/PETSCII typing, line auto-numbering, BASIC-V2 lint/folding, renumber/minify/prettify and C64 memory debugging. Phone errors are authoritative; this is not a claimed full desktop parser of the evolving language. C64U/VICE transfer guards prevent a Pocket READY. tab from becoming a PRG. Explicit profile selection survives Save As and closed-tab restoration; `.pbas` is recommended for disk persistence.

Enter the phone's base URL (for example `http://192.168.1.20:6401`, without the namespace) and temporary token. Discover/Connect checks both descriptors and the granted instance. Load, Load and run, Run memory, Stop, immediate command and program input use the exact-source client. A load does not imply a file save or editor synchronization on the phone. Retry exact request preserves the original envelope/generation; Query receipt resolves retained outcomes. Uncertain outcomes disable new mutating actions except Stop until queried/retried. An urgent Stop preserves the original unresolved envelope for later query/retry; request IDs/instances/generations are logged without tokens or source. No mutation is automatically replayed after reconnect. A native HTTP 202 or applied receipt is not game/program completion.

Observe output uses a cancellable, non-overlapping loop and the same per-window request gate as actions. It does not pile requests behind the native mailbox. It displays history-gap notices, caps the desktop transcript at about 64 KiB characters and retains at most 100 diagnostic entries. Double-click a located error only navigates when the current source exactly matches the last applied upload, its interpreter identity matches and its location is a program source; edited source or library/IMMEDIATE errors do not silently jump into the wrong document. Labels and physical lines remain distinct.

The window owns one redirect-disabled HttpClient and cancellation lifetime. Tokens live only in the password field/session memory and are cleared on disconnect/close. Disconnect cancels local requests/observation; it does not pretend an accepted phone action was rolled back or that the phone's grant was revoked. Use the phone's RUN STOP/Reclaim Local to revoke. Close drains owned operations before disposing client/gate/cancellation resources. A changed instance or lease requires explicit reconnect, never automatic ownership transfer. Desktop polling is separate from the phone's render loop and future Bifrost terminal pacing.

Acceptance checklist on real Windows/S24: load optional-label/FUNCTION/USE/DATA source from a `.pbas` tab; verify exact source/case/Unicode, unchanged original C64 tab and phone file-editor draft, native save/reopen/closed-tab profile, load-only vs run, immediate GET polling/input, yielding-loop Stop, observe gaps/errors, safe source navigation after edits, token revocation, restart identity, cancellation/uncertain retry, close while observing and continued C64U/VICE behavior. CI compiles WPF and runs all existing tests plus protocol/profile regressions. It cannot prove live WPF interaction or physical LAN lifecycle.
