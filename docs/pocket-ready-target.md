# Pocket READY. desktop protocol client

The client uses `/pocketready/v1/`, matching Pocket READY. PR #47. The Ultimate client keeps its independent `/v1/` API; there is no `/pr/` naming convention to preserve. Control/output support depends on Pocket READY. PR #48 (after #46 and #47). The desktop target/editor window is the following stacked READYCode PR, not part of this transport slice.

`PocketReadyClient` retains its injected, caller-owned HttpClient. **Configure its handler with AllowAutoRedirect=false** before using authenticated mutations; never silently follow a redirect carrying source. Tokens are attached per request, never to DefaultRequestHeaders, URLs, files or settings. Discovery remains unauthenticated; control requires the temporary token from the phone's explicit ALLOW CONTROL action. No desktop method grants control. Plain HTTP does not encrypt the token/source; use a trusted LAN. The WPF host supplies an owned redirect-disabled client and disposes it on close.

`GetControlAsync` validates advisory instance/controller/lease/generation/phase. `PocketReadyOperation.Create` preserves exact UTF-8 BASIC source (including optional labels, Unicode and line endings), assigns one operation ID and enforces source/input bounds. `ExecuteAsync` POSTs once, polls its ticket with a cancellable delay and returns an application receipt. It never automatically retries a mutation. Keep the immutable envelope after timeout, cancellation or transport failure: an action may already have applied. Deliberately retry that same envelope/ID or use `GetReceiptAsync`; do not manufacture a new ID for an uncertain action. A rejected application receipt is distinct from a delivery rejection/HTTP exception. Neither applied nor HTTP 202 means program completion.

`ReadOutputAsync` retrieves at most two events, validates monotonic next/latest cursors, bounds text and located diagnostic metadata and exposes gap warnings. It is lossy observation, not a Bifrost terminal spool. `PocketReadyContract.SourceId` matches the interpreter's UTF-16 FNV source identity for safe diagnostic navigation. Do not navigate into an edited document or another library merely because its line number exists.

All awaits use ConfigureAwait(false). Header/body reads and ticket polling share caller cancellation and an overall configurable deadline (15 seconds by default). JSON depth is bounded; discovery remains 64 KiB and control responses 256 KiB, checking both declared and actual bytes. Strict UTF-8 rejects invalid bytes. Requests/responses/streams/deadline sources are disposed. The caller's HttpClient remains alive. Source limits are 640 KiB UTF-8, JSON requests 4 MiB, input 1–16 UTF-16 code units. Unknown additive metadata/minor versions remain compatible; required fields and incompatible identities/major versions fail.

C64U/VICE, PRG conversion, assembly and debug APIs are unchanged. The application is still .NET 8 WPF. Run `dotnet test ReadyCode.Tests/ReadyCode.Tests.csproj -c Debug` on Windows; CI builds the full application and existing tests. HTTP doubles cover namespace/proxy paths, exact source, receipt/ticket identity, no implicit retry, cancellation, source/response limits and UTF-8. Real Windows-to-S24 networking and WPF interaction remain physical acceptance gates. This is a user-authorized stack; merge the client PR before its desktop UI child, and server #46 → #47 → #48 before testing the combined feature.
